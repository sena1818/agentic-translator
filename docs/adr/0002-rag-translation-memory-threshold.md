# ADR-0002: 以术语表外重复短语一致率作为 RAG 翻译记忆的立项门槛

日期: 2026-07-13
状态: 提议中（决策规则已定，最终结论待真实评测数据回填）

## 背景

翻译系统已有术语表（Glossary）强制统一术语译名，但术语表之外、在文档中反复出现的短语
（如某作者惯用的意象、某论文的自造概念）没有任何机制保证每次译法一致。一个常见的加强手段是
文档内翻译记忆（RAG，用 sqlite-vec 检索已译片段作为上下文）。但 RAG 会显著增加复杂度与检索延迟，
只有在"重复短语译法确实飘忽"时才值得做。需要一个量化门槛来决定做不做，而不是凭感觉堆技术。

## 决策

1. **量化指标**：术语表外重复短语的**译法一致率**。定义见 `src/evaluation/consistency.py` 与
   `docs/evals/methodology.md`：在按块对齐的 (原文, 译文) 语料上，抽取跨块重复、未被术语表覆盖、
   首尾非停用词的英文 n-gram，对每个短语求其各出现块译文的最长公共中文子串作为"译法签名"；
   有足够长的公共中文子串即判为一致。一致率 = 一致短语数 / 候选短语数。

2. **门槛 0.90**：
   - 没有候选短语 → `rate=null`、`decision=insufficient-data`，不能推断为 100% 一致或据此决策。
   - 一致率 **≥ 90%** → **不立项 RAG**，由本 ADR 记录不做的理由（单块翻译已足够自洽，
     RAG 的复杂度与延迟不划算）。
   - 一致率 **< 90%** → 重复短语译法飘忽，**另立文档内翻译记忆（sqlite-vec）的 PRD**。

3. **数据来源**：一致率取评测"生产基线"（langgraph + 多 Agent 开 + 术语表有）在评测数据集上的
   逐块产出，随三组对照评测一并由 `translator-eval` 产出，落在 `docs/evals/results/report.json`。

## 备选方案

- **无条件上 RAG**：叙事上更"高级"，但很可能是过度工程；若重复短语本就一致，等于白增延迟与复杂度。
- **人工抽检译法**：主观、不可复现，无法作为作品集里的量化依据。
- **更低/更高门槛**：0.90 是经验取值——留 10% 的飘忽容忍度；真实数据出来后可在本 ADR 修订。

## 后果

- 决策由数据驱动、可复现：换数据集或改门槛，结论随 `translator-eval` 重跑而更新。
- 最终状态二选一，届时把本 ADR 状态改为"已接受"并回填：
  - **不做**：记录实测一致率与"单块翻译已自洽"的结论；或
  - **要做**：本 ADR 降为背景，新开 sqlite-vec 翻译记忆 PRD。
- 该指标只覆盖"术语表外重复短语"这一维度，不评估跨文档记忆或风格迁移，超出范围者另行决策。

## 补充（2026-11-12，issue #24）：检索在本项目中的两种用途

本项目里"检索"有两种用途，目的、受众和判断依据都不同，不能互相援引来证明自己：

| | 翻译时的翻译记忆（本 ADR 的原问题） | 读者的语义检索（#24） |
| --- | --- | --- |
| 做什么 | 翻译某块时检索已译片段放进 Prompt，影响译文 | 读者用一句话找原话，跳到对照位置；不改译文 |
| 受众 | 翻译模型 | 读者、审校者、外部 agent（MCP 工具 `search_book_by_meaning`） |
| 依据 | 是否存在定位到的、记忆能解决的跨块译法错误，以及受控实验里质量与成本的净收益。一致率只作参考：#11 已把它改为按句对齐的启发式，它不能单独决定立项 | 用户明确需要按意思找原话；效果用"改写句 → 应命中段"用例的前 5 命中率度量，并与仅关键词检索对比（`docs/semantic-search.md`） |
| 失败代价 | 检索错片段会把错误译法带进新译文，需要质量评测把关 | 找不到或排序差，读者换个说法再查；不会污染译文 |
| 现状 | 未做 | 已做：段级关键词（BM25）+ 可配置向量模型，RRF 融合；未配置向量模型时退回仅关键词并提示 |

两者共用全书索引的段，但向量缓存只服务读者检索；以后若要做翻译记忆，需要按本 ADR 的依据另行论证，
不能因为"向量已经有了"就顺手接进翻译流程。
