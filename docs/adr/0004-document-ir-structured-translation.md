# ADR-0004：以 Document IR + 行内标签实现结构保真翻译

日期：2026-11-09
状态：已接受（实验分支，默认开启，可配置回落）

## 问题

旧流程把一段 Markdown 原样交给 LLM，靠 Prompt 要求"保留所有格式"，再用正则**数个数**校验
标题、图片、链接、代码围栏。以下错误都检测不到：图片顺序互换、链接地址被改写、标题层级变化、
`\[...\]` 形式的公式、表格错位、脚注丢失。双语对照以整块（约 3600 字符）为单位，HTML 还要
用正则把双语 Markdown 反向解析回来，原文含引用或分隔线时就会错位。EPUB 锚点在预处理与格式化
中被删掉，目录链接失效。

## 决策

1. **pandoc JSON AST 作为唯一事实来源**（`src/domain/document/document_ir.py`）。结构——标题层级
   与 id、列表、表格、图片、行间公式、代码块、脚注——由程序持有，始终不交给 LLM。
2. **行内标签协议**（`inline_codec.py`）。可翻译的行内列表编码成"文字 + 标签"：成对标签
   `<b1>…</b1>` 包裹格式化文字、可随语序移动；原子标签 `<m2/>` 代表公式/代码/图片/脚注/锚点，
   必须原样出现一次。LLM 物理上看不到公式与 URL，无法改写。
3. **段（Segment）为对齐与质检单位，块（Chunk）退化为调度批次**。一次调用翻译一个块内所有段，
   输入输出均为 `<seg id="N">…</seg>`；缓存、租约、审校仍以块为单位，与 ADR-0001/0003 兼容。
4. **确定性结构校验**。逐段比较源/译文的"结构骨架"（公式、代码、图片、链接地址、脚注、锚点的
   多重集合），不花 token、无误报；规则质检（术语、残留英文、数字）也下沉到段级。
5. **定点修复 + 安全回退**。只把不合格的段交给审校员；修复后仍丢结构的段回退为原文并标记，
   绝不输出缺公式、缺脚注的译文。
6. **回填而非拼接**。译文回填到源 AST 的深拷贝：标题 id、Div/Span 锚点保持不变，目录与交叉引用
   不会断；导出时做死链检查。预处理保留被内部链接指向的 `[]{#id}` 锚点。
7. **从 IR 直接渲染所有导出**：单语 Markdown、单元级双语 Markdown、双栏对照阅读器 HTML
   （段级 `data-seg` 双向跳转、悬停联动、按段锚点跟随滚动、目录、脚注浮层、问题段导航、
   MathML 离线公式）。导出只依赖"保存的源 Markdown + 块记录"，规划是确定性的，因此人工审校后
   可重渲染；审校改动了块结构时降级为块级对照。

## 备选方案

- **markdown-it token 流**：纯 Python，但不覆盖 pandoc 扩展语法（属性、脚注定义、fenced div），
  且需要自写 Markdown 回写器。pandoc 已是依赖且能无损往返，选 pandoc。
- **只把公式/URL 换成占位符（保护区）**：实现简单，但不能表达"加粗包裹的文字可以移动"，
  中文语序调整会破坏格式。
- **继续让 LLM 输出 Markdown + 更严格的正则校验**：校验仍然只能发现问题，不能保证正确。

## 后果

- 结构保真由构造保证；评测可新增"结构保真率"作为与"裸 LLM"对比的核心指标。
- 依赖 pandoc（Docker 镜像已安装；CI 安装）。不可用或解析失败时自动回落旧流程；
  `document_ir.enabled: false` 可整体关闭。
- 缓存键增加 `-ir1` 后缀，旧缓存不会串用。
- 规划约 1 秒、回填 + HTML 约 3 秒（18 万字符、3000 段的合成书）。
- 尚未覆盖：句级对齐、回溯 PDF 原页坐标（路线图 P5）、术语账本与全书一致性审计（P3）。
