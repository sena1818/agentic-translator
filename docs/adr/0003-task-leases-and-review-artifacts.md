# ADR-0003：任务租约、执行版本与结构化审校产物

日期：2026-10-03
状态：已接受

## 问题

单靠 processing 状态和 updated_at 无法区分慢任务与已中断 Worker。取消后旧对象仍可能覆写终态，多次执行也可能共用输出路径。仅保存拼接后的 Markdown 会丢失逐块质量信息，双语 HTML 反向解析引用和分隔线容易损坏代码与引用。

## 决策

- 任务认领在 SQLite 事务中完成，生成 execution_id、worker_id 和 lease_until。独立心跳续期；过期租约可重新排队，取消或失去租约后停止执行。
- 状态更新校验当前执行版本、processing 状态和有效租约。终态不可由旧任务对象推进。旧 schema 通过新增字段迁移，兼容历史输出文件。
- 创建任务时冻结配置与术语表。每次执行使用独立转换目录和结果目录，以版本校验发布 artifact_dir。转换完成标记允许重用完整转换结果。
- 块记录保存原文、译文、质量报告和修复/缓存标记。审校、预览与双语导出统一读取记录；Markdown 渲染保持表格、引用和代码结构，默认关闭原始 HTML。
- 人工编辑生成新产物目录，通过原产物版本比较后发布，并重新计算任务质量摘要和状态。失败保存不丢弃前端草稿；并发修改明确提示刷新。
- 默认重试失败块；指定重译块绕过旧缓存。其余成功记录作为恢复输入，保留人工编辑。缓存包含上下文与质检配置，文档画像可复用。
- 同一服务地址与 API 账号在共享 SQLite 中使用并发租约和滚动 RPM 窗口，覆盖所有模型角色；模型 SDK 重试关闭，显式重试每次计入预算。
- Application 用例负责状态迁移、快照和产物发布；Persistence / Filesystem / Converter 实现实际 I/O。旧 API 服务入口保留兼容导出。

## 边界与验证

本实现适用于共享本地数据目录的多进程 Worker。跨主机部署需共享持久化与集中请求预算，不能仅靠各主机独立 SQLite 横向扩展。

回归测试覆盖取消终态、过期租约、旧执行版本、重译保留人工修改、缓存故障、资源越界、结构化导出和前后端契约。浏览器验收使用临时数据库、假模型与生产构建；真实模型质量需另行付费评测，Docker 镜像需在具备 Docker 的环境构建验证。
