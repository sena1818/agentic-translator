# ADR-0005：手写 agent 运行框架，LangGraph 只做外层编排

日期：2026-11-12
状态：已接受

## 背景

PRD #10 只在两处使用 agent：翻译前的术语 agent（对有歧义的候选查证后定译名）和翻译后的审校 agent
（对被标记的问题分诊）。这两处的共同点是步数事先无法确定：要查几处上下文、要不要翻下一页，
由模型看了观察结果再决定。主翻译流程仍是固定工作流（ADR-0001），不改成 agent 自主规划。

需要的能力很具体：推理循环、工具注册与参数校验、三重预算、死循环检测、长输出分页与上下文压缩、
按条目隔离上下文、逐条目落盘恢复、可回放的追踪、结论必须引用证据。

## 决策

1. **运行框架手写**（`src/infrastructure/agent/`），不使用 LangGraph 的预制 ReAct agent、
   LangChain AgentExecutor 或其他框架的 agent 类。
2. **LangGraph 继续作为外层编排**。agent 通过 `as_graph_node()` 包成一个普通节点：图状态里只有
   输入条目和最终结局；节点内部的多步循环、上下文和预算由本框架负责。何时运行、与翻译流程的先后、
   并发度仍由图决定。
3. **动作协议用文本 JSON**（tool / submit / handoff 三种），不用各家原生 tool calling。
   DeepSeek、Gemini、本地模型和测试假模型走同一条路径，回复原文可直接落盘和回放。
4. **一切失败降级为转交人工**：预算用尽（`budget:steps|tokens|tool_calls`）、重复调用（`loop:`）、
   模型主动放弃（`agent:`）都返回 `status=handoff` 并写明原因。只有模型调用本身的异常
   （网络、额度）向上抛，由调用方重试；已完成的条目已经落盘，不受影响。

### 各部分怎么做

| 关注点 | 做法 | 位置 |
| --- | --- | --- |
| 循环 | 模型回复 → 解析动作 → 执行工具 / 校验结论 / 转交 → 观察写回上下文；以提交、转交或预算用尽结束 | `runner.AgentRunner.run` |
| 工具 | 注册名称、说明、参数 schema（JSON Schema 子集，无额外依赖）；校验失败、未知工具、工具抛错都作为观察返回 | `tools.ToolRegistry` |
| 预算 | 步数、token（优先用服务端用量，缺失时按字符估算）、工具调用次数三重上限 | `runner.AgentBudget` |
| 死循环 | 同一工具同一参数第二次出现时不执行，注入"结果见 E2，换一种查法"；提示后再重复则终止 | `runner.AgentRunner.run` |
| 上下文 | 工具完整输出存为证据 E1、E2……，观察只给第一页，内置 `read_page` 翻页；只有最近一步保留完整回复与观察，更早的步骤压成"动作摘要 + [E3] 模型写的一行 note"；提示长度不随工具输出增长 | `context` |
| 条目隔离 | 每个条目新建上下文与证据库，系统提示里只带"全局已决定事项"的摘要（条数和每行长度有上限） | `runner.summarize_decided` |
| 恢复 | 每完成一个条目向 JSONL 追加一行结局并 fsync；重跑时跳过已完成的条目 | `trace.Checkpoint`、`run_items` |
| 结论校验 | 引用的证据编号必须存在且至少一个；可挂业务校验函数；不通过时把原因作为观察返回，要求重做 | `runner._reject_reason` |
| 追踪 | 每步记录输入消息、回复、token、上下文长度、工具调用与输出、结局；模型调用另经 LangChain 回调进入 Langfuse 与 `UsageMetadataCollector` | `trace.JsonlTracer`、`model.RunnableChatModel` |
| 回放 | 用追踪里的模型回复和工具输出重跑，不调用模型、不执行工具，结局与原运行一致 | `runner.replay` |

## 为什么不用现成的 agent

- **护栏要可控**。预制 agent 的循环把预算、重复检测、观察压缩藏在框架内部，难以按"条目"为单位
  落盘恢复，也难以把"结论必须引用证据"做成循环内的拒绝-重做。这些恰好是本项目要度量和展示的部分。
- **可测**。手写循环只依赖一个 `ChatModel` 协议，测试用脚本化假模型就能覆盖正常提交、工具报错后恢复、
  重复调用终止、超预算降级四条路径，并断言上下文长度上界，不需要网络。
- **代价可见**。每步的 token 与上下文长度都在追踪里，阶段成本可以单独报告（PRD 要求每个新阶段单独统计）。
- 代价是要自己维护几百行代码，没有框架的生态集成；可观测性通过复用现有 LangChain 回调弥补。

## 不做的事

- 不让 agent 规划主翻译流程；不为每类问题单独建 agent，只有术语和审校两个。
- 不用 LangGraph checkpointer 保存 agent 内部状态：条目级 JSONL 已够恢复，步内状态丢了就重跑该条目。
- 不做并行工具调用和多 agent 对话。

## 验证

`tests/test_agent_harness.py`：四条路径、结论校验、分页与压缩、15 步运行中提示长度有上界、
条目隔离、中断后重跑不重复已完成条目、JSONL 追踪回放结局一致、作为 LangGraph 节点运行、
LangChain 适配器上报 token 并触发回调。
