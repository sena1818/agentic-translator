# ADR-0006：阅读遍默认关闭

- 状态：已采纳（2026-11-12），待真实模型消融后复审
- 相关：issue #17，[阅读遍消融](../evals/reading_pass.md)，[各阶段开关与成本](../cost-switches.md)

## 背景

原来的文档画像由分析员对全书首、中、尾三段采样后写成，覆盖不到中间章节才出现的定义；术语候选只看原文的
字面统计，书里被当作概念使用的小写常用词（hole、dust、solid）抓不到。#17 增加了一个可选阶段：翻译前按章顺序
读完全书，逐章写笔记，只带压缩后的累计状态进入下一章，产出覆盖全书的画像与第四路术语候选。

## 决定

1. **阅读遍是固定流程，不是 agent。** 章节顺序和每章要做的事都事先确定，不需要模型决定下一步；
   只借用了 agent 框架（ADR-0005）里"观察压缩"的思路：累计状态按确定性规则压缩，渲染文本有硬上限。
2. **默认关闭**（`multi_agent.reading_pass.enabled: false`）。
   - 成本：Cyclonopedia 上 39 次调用、约 19–28 万 token，纯翻译的 23–34%（提示长度实测，输出粗估）。
   - 收益：召回提升需要真实模型实测，本次未测；不调用模型的多路候选已把藏起条目的召回从 34% 提到 55%。
   - 用户要求显著增加 token 的阶段一律可选、默认关闭。
3. **开启时画像替换首中尾采样**，但随每块发送的提示文本限制在 1200 字符，与原画像相当，
   避免"画像更全"变成每块都多付一份成本。
4. **笔记按章缓存**，键串成链：中断续跑不重复花费，某章原文变化时只重读它和之后的章节。

## 复审条件

用真实模型跑 `translator-reading-bench --model`：若"多路 + 阅读遍"相对"多路"在出现 ≥ 2 次的条目上多找回的
数量明显（例如 ≥ 5 条）且误判没有增加，考虑在"全开"配置里推荐开启；默认值仍取决于成本预算。
