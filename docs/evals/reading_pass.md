# 阅读遍消融：成本与术语召回

日期：2026-11-12。对应 issue #17，结论记在 [ADR-0006](../adr/0006-reading-pass-off-by-default.md)。

## 阅读遍做什么

翻译前让分析员模型按章顺序读完全书（`src/pipelines/glossary/reading_pass.py`，纯逻辑在 `src/domain/rules/reading_pass.py`）：

- **分章**：按全书索引的章节路径分组；短于 3000 字符的相邻章节合并读，长于 24000 字符的章节切成几部分读。
- **每章一次调用**：输入本章原文和压缩后的累计状态，输出结构化笔记——本章摘要、到本章为止的全书概括、
  新出现的概念（原文写法、中文含义、定义位置）、被赋予特殊含义的常用词、文体说明。
- **累计状态有上界**：最近 3 章摘要全文、更早的 12 章各一行短摘要、按提及次数排前 30 的概念和前 10 个特殊用词，
  渲染文本硬上限 4000 字符。压缩是确定性规则，不额外调用模型；读到第 300 章也不再增长（有测试断言）。
- **产出一：全书画像**，替换原来首中尾采样的分析员画像。章节概览与术语提示每条带章节出处（"第 3 章《…》"、
  "首见第 5 章《…》"）；章数多时相邻章合成一行（"第 4–6 章"）。画像随每一块发送，整段提示文本上限 1200 字符，
  与原画像（Cyclonopedia 基线约 1k 字符）相当，所以不会让每块的提示明显变长。
- **产出二：概念候选**，作为术语候选的第四路来源（`reading`）：笔记里在原文中真实出现的概念与特殊用词，
  在前几路之外另有 60 条配额。
- **续跑**：每章笔记读完即写缓存，键由"前一章的键 + 本章原文 + 配置"串成，中断后重跑不重复花费；
  某章原文变了，它和之后的章节重读。调用失败的章不写缓存、阅读继续，重跑时补读。
- **开关**：`multi_agent.reading_pass.enabled`，默认关闭。关闭时不调用、画像与术语账本与旧版一致（有测试）。

## 成本（Cyclonopedia，实测提示长度，输出粗估）

```bash
translator-reading-bench --source <Cyclonopedia>.md --glossary data/glossaries/CPglossary.json --translation-tokens 817372
translator-reading-bench ... --full-notes
```

不调用模型，用假模型跑完整个阅读遍：分章、累计状态、提示长度都是真实的。上下界分别是笔记为空、每章笔记写满上限。

| | 笔记为空（下界） | 笔记写满（上界） |
| --- | ---: | ---: |
| 阅读单位（章） | 39 | 39 |
| 模型调用 | 39 | 39 |
| 提示 token（按字符粗估） | ≈175k | ≈268k |
| 输出 token（每章 350 粗估） | ≈14k | ≈14k |
| 合计 | ≈189k | ≈282k |
| 占纯翻译（同一本书基线 817,372 token） | 23% | 34% |
| 累计状态最大 | 935 字符 | 4000 字符（触到上限） |

另外画像随每块发送：上界情形下 1149 字符 ≈ 915 token × 242 块。原画像约 1k 字符，两者相当，这部分不额外增加成本。

完整输出：[results/reading_pass.md](results/reading_pass.md)、[results/reading_pass_full_notes.md](results/reading_pass_full_notes.md)。

## 召回（未测）

召回需要模型真的读书。命令已备好，加 `--model --config <配置>` 后阅读遍只跑一次，再按 `translator-term-bench`
相同的两折藏起术语表条目，比较四组召回：旧版（只抽专名）、旧版 + 阅读遍、多路、多路 + 阅读遍。

这次**没有用真实模型跑**：需要付费密钥，且阅读遍单独一项就要约 20–28 万 token。等 #25 用真实模型做前后对比时一起跑。
作为参照，不调用模型的多路候选已把召回从 34% 提到 55%（[term_candidates.md](term_candidates.md)），
仍找不回的主要是书里以小写出现的常用词（Solid、Fluid、Swarm、Paranoia），这正是阅读遍"特殊用词"一项瞄准的部分。

## 默认值的依据

- 成本确定且不小：纯翻译的 23–34%，在"全部开启不超过纯翻译约 2.5 倍"的预算里占得不少。
- 收益尚无实测：召回提升要真实模型才能测，现有证据只说明它瞄准的缺口存在。
- 用户要求：显著增加 token 的阶段一律做成可选项、默认关闭。

所以默认关闭。用真实模型测出"多路 + 阅读遍"比"多路"多找回的条目数后，再决定是否改默认，结论补进 ADR-0006。
