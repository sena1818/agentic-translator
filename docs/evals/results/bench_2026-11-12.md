# 新旧版本对比（2026-11-12，四本书节选）

这是 #25 要求的真实评测。对比三组：

- **旧版**：`f356bb2`，即第二轮改动之前的版本；
- **新版·默认**：当前 main，配置不改；
- **新版·全开**：开启全部可选阶段，包括多路术语候选、阅读遍、术语 agent、模型语义质检和审校 agent。配置写法见 [cost-switches.md](../../cost-switches.md#开启全部可选阶段)。

译文和原文都不入库，这里只记录数字。

## 设置

| 项 | 值 |
| --- | --- |
| 翻译模型 | `deepseek-v4.1-flash-1017`（TokenRhythm，输入 1 元 / 百万 token，输出 4 元 / 百万 token） |
| 样本 | 四本书各取一段连续节选，合计 973 段、182 块 |
| 书目 | Shannon & Weaver《The Mathematical Theory of Communication》、Wiener《Cybernetics》、Thacker《Tentacles Longer Than Night》、Negarestani《Cyclonopedia》（使用 `CPglossary.json`） |
| 打分 | 三组都用新版的同一套检查器离线打分：结构对齐、缺段、照抄原文、规则加启发式语义质检、专名一致性、非文字审计 |
| 盲评 | 每本书抽 25 个正文段，分别比较"旧版 vs 新版·默认"和"旧版 vs 新版·全开"。A、B 顺序随机，两份译文相同的不送裁判，直接计为一致。裁判是 `deepseek-v4.1-flash-1017`，与翻译模型相同；由于余额限制，没有改用更强的模型。盲评中途账户余额耗尽（402），只完成了一部分 |

## 结构与质检

三组的结构指标完全一致：分块都与计划对齐，没有缺段，没有失败块。非文字问题都是 3 处（Shannon 1 处、Cyclonopedia 2 处）。

| 书 | 段数 | 被标出问题的段占比<br>旧 / 默认 / 全开 | 照抄原文的段<br>旧 / 默认 / 全开 | 专名一致性<br>旧 / 默认 / 全开 |
| --- | ---: | --- | --- | --- |
| Shannon | 423 | 0.113 / 0.113 / 0.097 | 33 / 44 / 32 | 0.868 / 0.891 / 0.815 |
| Cybernetics | 119 | 0.067 / 0.034 / 0.042 | 0 / 0 / 1 | 1.000 / 0.991 / 0.970 |
| Tentacles | 156 | 0.083 / 0.090 / 0.077 | 0 / 0 / 0 | 0.922 / 0.912 / 0.925 |
| Cyclonopedia | 275 | 0.069 / 0.084 / 0.095 | 9 / 9 / 10 | 0.925 / 0.947 / 0.935 |
| **合计** | 973 | **0.090 / 0.092 / 0.086** | **42 / 53 / 43** | — |

说明：

- "被标出问题的段"是指检查器在终稿里仍能找到 high 或 medium 级问题的段。这套检查器同时也是新版修复流程用的检查器，所以这个指标会偏向新版。
- 照抄原文的段主要是公式、符号表和参考文献条目，大多本来就不需要翻译。
- 专名一致性的统计范围是出现至少 3 次的大写词，计算主导译法所占的比例。这个指标噪声很大：漂移列表里多是 `Suppose`、`Let`、`THE` 这类句首大写词，以及 `City`、`Time` 这类普通词，真正的专名只有少数几个。它只能作参考，不能单独拿来判断好坏。

## 成本与用时

| 组 | token（输入 / 输出） | 费用（元） | 相对旧版 | 用时 |
| --- | --- | ---: | ---: | ---: |
| 旧版 | 48.8 万 / 13.9 万 | 1.04 | 1.0× | 9 分钟 |
| 新版·默认 | 50.4 万 / 13.3 万 | 1.04 | 1.0× | 10 分钟 |
| 新版·全开 | 500 万 / 41 万（含审校） | 6.65 | **6.4×** | 131 分钟 |

全开组的 token 去向，以 Cyclonopedia 节选为例。默认组总计 16.4 万 token：

| 阶段 | token | 备注 |
| --- | ---: | --- |
| 术语 agent | 50.9 万 | 处理到 `max_items: 40` 的上限，每条平均约 1.27 万 token，接近单条上限 1.6 万 |
| 审校 agent | 77.4 万 | 进入 agent 的问题有 107 条，每条平均约 7.2k token，单条最多约 1.4 万 |
| 翻译、阅读遍、账本、模型语义质检、修复 | 约 32.8 万 | 比默认组多约 16 万 |

结论：

- 原先文档估计全开约为纯翻译的 2.5 倍，实测在节选上是 **6.4 倍（按费用）**、**约 8.5 倍（按 token）**。主要原因是术语 agent 和审校 agent 的用量按条数计，跟篇幅无关。术语 agent 固定处理 40 条，放在节选上占比被放大；整本书的倍数会低一些，但审校 agent 的条数会随问题数增长。
- 用时增加约 15 倍。主要原因是逐段模型语义质检和两个 agent 的请求数多，TokenRhythm 的限流是每窗口 30 次，请求只能排队。

## 结论

- **新版·默认与旧版质量持平，成本持平。** 结构指标、离线质检和盲评都没有显著差别。第二轮的默认改动没有带来可测的退步，也没有在译文质量上带来可测的提升；它的价值主要在可观测性、断点续传和导出质量这几方面。
- **新版·全开的代价约为旧版的 6.4 倍，但没有可测收益。** 离线质检里被标出问题的段从 9.0% 降到 8.6%，可以算在检查器偏向新版的范围内；盲评略偏向旧版，但不显著。按 cost-switches.md 的原则（"没有可测收益的阶段不保留"），这些阶段应继续默认关闭。术语 agent 和审校 agent 在降低成本之前，不建议整本开启。
- 下一步如果要证明可选阶段的价值，需要更强的裁判模型（不能与翻译模型相同），以及更多样本。另外可以只开单个阶段做消融，而不是全开。

## 复现

评测脚本没有入库，因为它们依赖本地书籍。流程如下：

1. 用 pandoc 把 EPUB 转成 Markdown，参数为 `-t markdown-raw_html-native_spans-bracketed_spans-native_divs-fenced_divs-link_attributes-header_attributes --extract-media`。
2. 每组用 `TranslationEngine` 的 `plan_chunks` 和 `translate_batch` 翻译。全开组翻译完后，再跑 `ReviewTriageService.triage`。
3. 用当前版本的 `segment_recheck`、`BookIndex.renderings` 和 `StructuredExporter` 对三组统一重新打分。
