## 首轮发现并已修复的规则误报

| 现象 | 原因 | 修复 |
|---|---|---|
| "2008年""47页"被报缺少数字 | 正则 `\w` 把中文当单词字符，数字边界失效 | 数字边界只看 ASCII |
| 普通用词 earth / solid 被强制译成"地球""固态"，修复后译文变差 | 术语匹配为大小写无关子串 | 整词匹配；`quality.glossary_respect_case` 下首字母大写术语不约束小写用法（论文配置关闭） |
| 斜体书名 → 《》、引号 → “” 被报格式丢失 | 中文惯例本就如此 | 斜体/引号不计入格式差异 |
| Markdown 中破折号写成 `------` | pandoc smart 扩展转义 | 输出关闭 smart，直接写 Unicode |
| 文内目录与标题措辞不一致 | 分属不同块各自翻译 | 目录项文字按译后标题同步 |

## 仍存在的问题（下一步）

- 人名/概念跨块不一致：Parsani → 帕萨尼 ×6 / 帕尔萨尼 ×1；Hole → 孔洞 / 洞穴。需要 P3 术语账本。
- 术语表译名自带英文括注时，每次出现都带括注，读起来冗余。
- 样本为合成测试章，尚未用真实整本书验证（EPUB 转换噪声、长书速率限制）。

## 成本估算（按本次 token 外推）

约 1.3 token 输入 / 0.4 token 输出 每源字符。一本 60 万字符（约 10 万英文词）的书：
约 **80 万输入 + 25 万输出 token**，约 190 次请求（另加少量修复）。免费层可行但受每日请求数限制，
可能需要分 1–2 天跑完；断点缓存保证中断后不重复花费。

### 本轮修复

| 问题 | 修复 |
|---|---|
| 免费层每日额度（gemini-3.5-flash 每天 20 次）用完即整块失败 | 读取原始响应体识别"每日额度"，自动切换 `fallback_models`；全部用完抛明确错误，断点续跑 |
| 每分钟限流只退避 ~30s | 按服务端 "retry in Ns" 等待，无提示时分钟级退避 |
| EPUB 目录链接全部失效 | 清洗前修复链接：段落锚点丢失时退回章首；`#` 在 id 中改写为 `__` |
