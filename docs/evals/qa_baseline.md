# 质检基线：注入错误召回率与误报率

日期：2026-11-12。代码基线：issue #11 合入时的 `TranslationValidator`（`src/core/validator.py`）；末节为 #20 的语义质检。
不调用任何模型、不需要密钥，下面两组数字都可以一条命令复现。

## 怎么测的

取正确的 (原文, 译文) 段对，用程序把译文改坏成七类已知错误之一，再交给规则质检：

| 类型 | 注入方式 | 只在什么条件下注入 |
| --- | --- | --- |
| 反转否定 | 删掉译文里的否定词（没有、不、未、无……） | 原文含 not / never / no / n't 等 |
| 改变情态强弱 | "可能"→"必然"、"表明"→"证明"；"必须"→"可以" | 原文含 may / might / suggest 或 must / always / prove |
| 交换数字 | 译文里两个不同数字互换位置 | 译文至少有两个不同数字 |
| 漏译半句 | 删掉译文后半的分句（至少 6 个汉字） | 单行正文、至少两个分句 |
| 换错术语 | 术语表译名换成另一个条目的译名 | 原文含该术语、译文含该译名 |
| 改链接地址 | Markdown 链接 URL 最后一个字符改掉 | 译文有链接 |
| 改代码内容 | 代码里前两个标识符互换 | 译文有行内或围栏代码 |

- **检出**：改坏后的译文报出了原样译文上没有的问题（只比新增问题，原样段对上本来就有的误报不算检出）。
- **误报**：原样段对上报出任何问题。
- 注入错误比真实错误规整，召回率只说明质检能否抓住这类已知错误，**不是**真实译文的检出率。

实现：`src/evaluation/injection.py`；命令：`translator-qa-bench`（`src/evaluation/qa_bench.py`）。

## 结果一：仓库自带段对

36 条自撰短句（`datasets/injection_pairs.json`，不含版权文本），外加
[深化方案](translation-quality-deepening.md) 记录的六个反例作为种子用例。

```bash
translator-qa-bench --out docs/evals/results
```

| 错误类型 | 注入数 | 检出数 | 召回率 |
| --- | ---: | ---: | ---: |
| 反转否定 | 10 | 0 | 0% |
| 改变情态强弱 | 8 | 0 | 0% |
| 交换数字 | 6 | 0 | 0% |
| 漏译半句 | 15 | 3 | 20% |
| 换错术语 | 6 | 6 | 100% |
| 改链接地址 | 3 | 0 | 0% |
| 改代码内容 | 3 | 0 | 0% |
| **合计** | 51 | 9 | **18%** |

- 原样段对误报：0 / 36。
- 六个种子反例：**全部漏检**（与深化方案记录一致）。
- 漏译的 3 次检出都是因为被删的半句里带数字，触发了"缺少原文数字"；不是规则识别出了漏译。

完整表格与漏检示例：[results/qa_injection.md](results/qa_injection.md)。

## 结果二：Cyclonopedia 真实译文（本地）

2026-11-11 基线运行（`config/tokenrhythm.yaml`，deepseek-v4.1-flash，见 `data/output/baseline_cyclonopedia_2026-11-11/`）
的 242 块中，按空行拆段且两侧段数相同的 948 个段对，术语表用 `CPglossary.json`。书籍原文不入库，这里只记数字。

```bash
translator-qa-bench --records data/output/baseline_cyclonopedia_2026-11-11/Cyclonopedia.records.json \
  --glossary data/glossaries/CPglossary.json
```

| 错误类型 | 注入数 | 检出数 | 召回率 |
| --- | ---: | ---: | ---: |
| 反转否定 | 366 | 3 | 1% |
| 改变情态强弱 | 179 | 0 | 0% |
| 交换数字 | 94 | 1 | 1% |
| 漏译半句 | 688 | 200 | 29% |
| 换错术语 | 491 | 470 | 96% |
| 改链接地址 | 0 | 0 | — |
| 改代码内容 | 0 | 0 | — |

- 原样段对上报出问题：180 / 948（19%）。这些段对未经人工核对，其中可能有真问题；抽看到的多为术语误匹配：
  原文里小写的普通词（sun、dust、solid）按不区分大小写的子串命中了术语表条目，译文没用该术语译名就被报错。
- 漏译 29% 的检出主要来自"缺少原文数字"、"残留英文"和术语缺失这类副作用，规则本身不判断句意是否完整。
- 这本书没有链接和代码，所以这两类没有样本。

## 读数

1. 规则质检能管住的只有**术语译名**这一类；否定、情态、数字角色、漏译、链接目标、代码内容基本看不见。
   这是 #20（语义质检器）和 #19（全书非文字审计）要补的部分，也是它们的验收基线。
2. 数字规则只比较集合，数字互换位置后集合不变，所以交换数字检不出来；链接与代码规则只数个数，内容变了检不出来。
3. 真实译文上 19% 的段被报问题，主要来自术语子串误匹配；改进术语检查时应同时看这个误报率。

## 裁判与一致率的修正（同一 issue）

- 裁判输出缺维度、分值非数字或超出 1~5 时，该条记为**无效裁决**并在报告中计数，不再补 3 分；
  准确性 ≤ 2 时综合分不超过准确性分，流畅度不能把严重误译拉回中等。
- 一致率改为按句对齐：签名只能来自短语所在的那一句，段数或句数对不上的段落不计入并单独计数。
  深化方案里"无关共同句子造成假一致"的反例（`buried engine`）现在判为不一致。

## 语义质检（#20）：规则 vs 规则 + 语义

`translator-qa-bench` 现在对每组段对同时跑两个检测器：`rules`（上面的规则质检）和
`rules+semantic`（规则 + 语义质检的确定性启发式）。启发式只比对表面信号：否定词有无与多少、
推测/断言措辞、`from X to Y`/`between X and Y` 里数字的先后与涨跌方向、译文汉字数与原文词数之比、
转折连接词，实现在 `src/domain/rules/semantic_signals.py`。不调用模型、不花 token。

### 自带段对（36 条）

| 错误类型 | 注入数 | rules 召回 | rules+semantic 召回 |
| --- | ---: | ---: | ---: |
| 反转否定 | 10 | 0% | 100% |
| 改变情态强弱 | 8 | 0% | 75% |
| 交换数字 | 6 | 0% | 50% |
| 漏译半句 | 15 | 20% | 100% |
| 换错术语 | 6 | 100% | 100% |
| 改链接地址 | 3 | 0% | 0% |
| 改代码内容 | 3 | 0% | 0% |
| **合计** | 51 | 18% | **78%** |
| 原样段对误报 | 36 | 0 | 0 |

六个种子反例：语义启发式抓到否定、情态、数字、漏译四个；链接与代码两个仍漏检（留给 #19 非文字审计）。

### Cyclonopedia 真实译文（948 段对，本地）

| 错误类型 | 注入数 | rules 召回 | rules+semantic 召回 |
| --- | ---: | ---: | ---: |
| 反转否定 | 366 | 1% | 22% |
| 改变情态强弱 | 179 | 0% | 41% |
| 交换数字 | 94 | 1% | 3% |
| 漏译半句 | 688 | 29% | 74% |
| 换错术语 | 491 | 96% | 96% |
| **合计** | 1818 | 37% | **62%** |
| 原样段对上报出问题 | 948 | 180（19%） | 217（23%） |

- 误报增加 37 段（+3.9 个百分点）。抽看到的主要是：段落里推测词和断言词分属不同句子、
  "without"/"but" 在原文里不表否定或转折、pandoc 原始 HTML 片段拉低了长度比。
- 否定召回在真实译文上低：哲学文本一段里常有多处否定，删掉一个后其他否定字还在，计数法只能抓到一部分。
- 交换数字几乎抓不到：书里的数字多是年份、页码、编号，很少出现 `from X to Y` 这类有方向的结构；
  数字配错对象（"36 小时、8 块 GPU" 互换）需要理解句意，这是模型检查要做的事。

### 模型语义检查：成本与"只查高风险段"

开启 `quality.semantic_check.use_model` 后，被选中的段按批（默认 12 段）送模型，要求输出
原文片段、译文片段、类型、严重度、理由，允许"无法判定"。下面的 token 是按提示字符数粗估，**未调用模型**；
模型版的召回率与误报率需要密钥，**尚未实测**（命令：`translator-qa-bench --semantic-model`，加 `--all-segments` 查全部段）。

| | 自带段对 | Cyclonopedia |
| --- | ---: | ---: |
| 段落数 | 36 | 948 |
| 高风险段（含否定/情态/数字/长句） | 21（58%） | 679（72%） |
| 全部送检的提示 token | ≈ 2,300 | ≈ 350,000 |
| 只送高风险段 | ≈ 1,400 | ≈ 316,000 |
| 对照：这些段原文 + 译文 token | ≈ 1,300 | ≈ 322,000 |

只查高风险段时，模型召回率的上限（注入错误落在高风险段的比例）：

| 错误类型 | 自带段对 | Cyclonopedia |
| --- | ---: | ---: |
| 反转否定 / 改变情态 / 交换数字 | 100% | 100% |
| 漏译半句 | 73% | 78% |

读数：模型检查的提示规模大致等于原文加译文本身，即在翻译之外再付一次接近全文的输入 token。
"只查高风险段"在论文类短句上能省约四成，在 Cyclonopedia 这种长段落文本上只省约一成（长段几乎都含否定或数字），
且会放过约两成的漏译。是否值得开模型检查，要等有密钥后实测它在启发式之上多抓到多少。
