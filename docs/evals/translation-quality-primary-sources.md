# 专业英译中的质量证据：一手来源研究

研究日期：2026-10-18。范围：理论／哲学著作和机器学习论文的英译中；目标是加深质量证据，不扩充产品面积。本文件是研究与设计建议，不是实施记录，也不表示已完成真实评测。

## 核心判断与证据边界

建议把项目目标从“更多块成功生成”改成“译文中的重要决定能够回到原始材料，错误能够被独立检查，改进能够在预先固定的评测中成立”。翻译不是通常能被绝对证明唯一正确的对象；可以严格验证部分结构与数值约束，并积累有范围、有不确定性的语义质量证据。下文将文献事实和本项目建议分开。

现有仓库事实：`docs/evals/methodology.md` 使用两个自撰摘选，每变体每样本一次真实翻译的设计，并由异源模型给三个维度打分；`docs/evals/results/report.md` 当前明确是 dry-run，占位分数不代表真实质量。ADR-0002 用重复英文短语出现块中最长公共中文子串作为一致性代理，并以 90% 为 RAG 立项门槛。以下方案应修订既有方法与 ADR，不能把研究建议写成现有系统已经具备的保证。

## 一、专家会额外做什么

**文献事实。** Freitag 等人的 MQM 研究让专业译者在完整文档上下文中标注具体错误，得出的系统排序与众包评审明显不同。这支持“谁评、看到什么上下文、标注什么错误”都会影响结论；该研究语言对为英德和中英，不能直接当作本项目英中哲学译文的有效性认证。[论文](https://arxiv.org/abs/2104.14478)

**项目建议。** 翻译之前先固定读者、用途、容许的解释程度和引用／术语规则。把以下任务加入现有流程的职责，而非增加无边界的 Agent 角色：

- 源文校勘：区分原作者的晦涩、故意双关和 OCR 损坏；保留疑点，不让译文替作者悄悄补成通顺论证。
- 关键命题核对：检查否定、条件、量词、因果、模态强弱，以及论文中的假设与结论。流畅度不能抵消这些错误。
- 术语决策：说明译法依据、适用语境、允许变体与争议；“符合自己整理的术语表”只证明遵守约定，不能证明约定正确。
- 全章复核：追踪代词、概念演变、引文层级与跨块依赖；在不知道系统版本的情况下判断改进。

## 二、从哪些原始材料入手

**文献事实。** Nougat 将科学 PDF 的页面图像转换为标记文本，其研究问题包含 PDF 中数学语义的丢失；PyMuPDF 官方文档说明 PDF 内部存储顺序不保证视觉阅读顺序，多栏文本不存在靠通用排序彻底解决的保证。Markdown 因而应视为转换产物，而非原始事实。[Nougat 论文](https://arxiv.org/abs/2308.13418)、[PyMuPDF 文档](https://pymupdf.readthedocs.io/en/latest/faq/index.html)

**项目建议。** 每项重要译文证据应从以下材料逐层建立，而非只拿已有 Markdown 和 JSON 术语表互相验证：

| 材料 | 用途与保留方式 |
| --- | --- |
| 实际采用版次的 PDF 页面、EPUB 内部 XHTML／脚注及出版信息 | 确认原文、版次、页码和阅读顺序；保留原文件哈希。EPUB 用章节与元素位置定位，不伪造稳定页码。 |
| 论文作者发布的版本、LaTeX 源码（若提供）、补充材料和勘误 | 核对公式、符号、表格与版本差异。源码也须与所采用 PDF 版本对应，不自动假定源码是最后版本。 |
| 作者在同一著作中的完整相关段落、注释与引用的原始文本 | 判定哲学概念、隐喻、引文边界和跨段指代；二手解释只能作为明确标记的辅助。 |
| 术语首次定义、作者用例、领域规范用语及已有译本的具体出处 | 支撑术语决策；已有译本是可比较的证据，不是无条件唯一答案。 |
| 真实运行失败块、人工改稿差异与原始模型响应 | 建立项目自身的错误分布，避免只在自撰容易样本上验证。 |

最小来源定位记录建议为 `document_hash + edition/version + page/epub_locator + source_span + chunk_id`；PDF 有坐标时再保留 `bbox`。定位不齐全应明确标为来源未核验。

## 三、具体方法与工具

### 1. 用错误证据替代只给总体印象分

**文献事实。** 研究者公开的 WMT MQM 数据将错误定位到文本跨度，并分别记录类别和严重性；提供 Marot 对 TSV 结果进行交互分析。其具体权重是研究设置，不能当作跨领域必然最优的常数。[作者仓库与 Marot 说明](https://github.com/google/wmt-mqm-human-evaluation)

**项目建议。** 扩展现有 `QualityReport` 的证据表达，让问题有原文／译文跨度、类别、严重性、理由、建议及来源定位。先覆盖误译、漏译、增译、术语错误和结构丢失；针对 ML 增加数字／公式变更，针对理论文本保留“存在合理歧义／待专家判定”。模型标注只是候选，人工确认另存，避免把模型意见写成已确认事实。Marot 可以直接分析导出的标注，无须先造新评测平台。

### 2. 术语正确性与文档一致性分别验证

**文献事实。** Alam 等人专门研究领域术语约束的评估，并执行术语针对性的人工评价；BlonDe 则研究句级指标难以表达的文档级现象。这支持分别测量术语与上下文问题，但它们原实验并非对本项目领域的直接验证。[术语评估论文](https://arxiv.org/abs/2106.11891)、[BlonDe 论文](https://aclanthology.org/2022.naacl-main.111/)

**项目建议。** 为关键术语保存 `concept_id、source_form、sense、approved_forms、forbidden_forms、evidence、scope`。自动检查是否在正确意义上使用适用译名；人工抽查正确性和变体是否合理。同一错误译法重复出现应计作“一致但错误”。最长公共子串可能来自无关的共同背景词，也可能排斥正确的同义表达；应以人工标注用例校准其误报／漏报，再决定是否保留此代理。ADR-0002 的 90% 暂不承担 RAG 架构决策，先重新验证测量对象与适用性；失败来源未必是缺乏检索。

### 3. 对源文提取与输出做分层核验

**项目建议。** 使用已有转换器；必要时用 PyMuPDF 的 `blocks/words/dict` 获取位置，用页面渲染检查多栏、公式和脚注。对公式、数值、引用键、脚注标识、代码、图表引用建立确定性检查，再让专家核对“公式周围的解释是否仍然表达同一命题”。字符相同只证明保真，不证明解释正确；多个转换器一致也不等于无误。[可用的文本位置接口](https://pymupdf.readthedocs.io/en/latest/faq/index.html)

### 4. 先校准裁判，再用它扩大筛查覆盖

**文献事实。** MT-Bench 研究记录了模型裁判的位置、冗长和自我偏好等问题，但任务不是专业翻译；对本项目只能提供风险假设，不能据此估算具体偏差。WMT24 仍使用 MQM 人工评审与有意构造的错误对照集检查指标；另一项 MT 研究发现，指标引导生成后的质量高估并不能仅靠换一个神经指标消除。[MT-Bench](https://arxiv.org/abs/2306.05685)、[WMT24 Metrics](https://aclanthology.org/2024.wmt-1.2/)、[指标偏差研究](https://aclanthology.org/2024.wmt-1.109/)

**项目建议。** 把“异源避免偏好”改为“异源可降低某些依赖，仍须在人类标注集校准”。建立少量但有代表性的挑战对：否定反转、数值替换、公式符号变化、漏掉限定语、术语错误、增补不存在的解释。测裁判的检出率、误报率与对系统 A/B 排序的一致程度；A/B 顺序交换，隐藏系统身份。开发时用来挑选和修复译文的裁判，不能成为最终质量增益的唯一依据。

## 四、除开发者和模型外，什么能支持结果可信

**文献事实。** Riley 等人研究多译者、样本分配与评分归一化如何影响 MQM 系统排序的稳定性；SacreBLEU 提供带配置签名的 BLEU／chrF 等指标以及配对统计检验。它们支持可复核的评测方法，不提供“某个分数即绝对正确”的解释。[稳定排序论文](https://aclanthology.org/2024.naacl-long.275/)、[SacreBLEU 作者工具](https://github.com/mjpost/sacrebleu)

**项目建议。** 建立四种相互补充的证据：

1. **可回查的原文**：审校者可以点到具体原页／章节，逐项检查漏译、数值和疑点。
2. **独立专家盲评**：与方案开发分离的双语领域审校者独立标注；重叠样本测一致程度，保留分歧，必要时由第三人裁决。至少包含懂领域的人，而不是只会中文的人。
3. **固定留出评测**：按文档拆分开发集与留出集，防止同书相邻块泄漏；采用代表性随机样本估计通常表现，另报困难样本的压力测试结果，不能将两者混成总体错误率。先做小规模试评，再根据错误率、文档相关性与预算确定样本量；不要宣称固定几十段足够证明全面优越。
4. **可审计运行包**：保留版本／提交、输入哈希、配置与术语快照、Prompt、模型标识、服务地址、时间、原始响应、修复前后差异、人工标注和计算脚本。固定产物能复算；云模型再次调用不保证逐字复现。

主结论宜报告严重错误数／每千源词错误数及其定义、漏译／增译率、术语正确率、文档级问题、人工修订耗时和成本。综合印象分可保留为辅助；流畅度不应在均值中掩盖严重误译。比较前固定基线、抽样与验收条件，报告配对差异和不确定性；跨块依赖存在时以文档或适当簇重采样，避免把同一文档的块当独立重复实验。SacreBLEU 可作有合适参考译文时的补充，不能代替该领域的专家语义判断。

“抽检未发现严重错误”必须同时交代样本范围和数量，不能写成“全书没有严重错误”；结论应限定于被测版本、材料与流程。

## 最小落地顺序

1. 固定一个真实代表文档及其原始来源，建立可回查定位；先查清提取错误与翻译错误各占什么。
2. 基于实际失败建立错误分类与少量专家校准用例，扩展既有质检／人工审校记录，而非另建平台。
3. 校准术语代理与模型裁判，修订 `methodology.md`、`CONTEXT.md` 中的证据强度措辞及 ADR-0002 的决策前提。
4. 冻结简单基线与一项针对已证实主要错误的修改，用独立盲评和留出材料验证；没有足够证据时报告“不确定”，不把测试流水线跑通当成质量提升。

上述顺序是工程建议，不是文献对本仓库效果的实证结论。研究没有访问付费模型、执行真实翻译评测，也没有验证现有译文是否合格。
